# 工作流触发模板功能规格说明

## 1. 功能概述

工作流触发模板功能允许用户将工作流执行信息保存为模板，方便快速触发相同的工作流。

## 2. 功能需求

### 2.1 保存为模板

- 在工作流执行详情页添加"保存为模板"按钮
- 点击后弹出对话框，要求输入模板名称
- 保存当前执行的仓库、工作流ID、工作流名称、Git Ref作为模板
- 模板持久化到数据库

### 2.2 模板列表

- 新增模板列表页面 (`/templates`)
- 显示所有已保存的模板
- 显示模板名称、仓库、工作流、分支、创建时间
- 支持删除模板功能

### 2.3 模板使用

- 在触发工作流页面，可以从模板快速选择填充表单

## 3. 数据模型

### WorkflowTriggerTemplate

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | int | 主键，自增 |
| Name | string | 模板名称 |
| Owner | string | 仓库所有者 |
| Repo | string | 仓库名 |
| WorkflowId | string | 工作流ID |
| WorkflowName | string | 工作流名称 |
| Ref | string | Git引用(分支/标签) |
| CreatedAt | DateTime | 创建时间 |

## 4. 页面设计

### 4.1 模板列表页面 (`/templates`)

布局:
- 页面标题: "触发模板"
- 模板列表表格
- 每行显示: 模板名称、仓库、工作流、分支、创建时间、操作(删除)
- 返回导航按钮

### 4.2 工作流执行详情页修改

在现有按钮区域添加:
- "保存为模板"按钮 (左侧，"再执行一次"按钮之前)

### 4.3 保存模板对话框

- 模态对话框
- 输入框: 模板名称
- 取消按钮
- 确定按钮

## 5. 技术实现

### 5.1 后端

- 新增实体类: `WorkflowTriggerTemplate`
- 更新 `GiteaExtensionsDbContext`
- 创建数据库迁移
- 在 `WorkflowService` 中添加模板CRUD方法

### 5.2 前端

- 在导航栏添加"触发模板"菜单项
- 创建模板列表页面 `Templates.razor`
- 修改工作流详情页，添加保存模板功能
- 使用Dialog组件或内联模态框

## 6. 验收标准

1. 可以在工作流执行详情页成功保存模板
2. 可以在模板列表页面查看所有模板
3. 可以在模板列表页面删除模板
4. 数据库正确存储模板数据
5. 页面UI符合项目现有风格
